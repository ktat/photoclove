# Improve Importing Photos

## 現在のロジック

1. ソース識別 (UUID生成)

- get_or_create_source_uuid() - 各インポート元に固有のUUIDを生成・取得
- .photoclove-uuid ファイルでソースを識別
- UUID生成に失敗した場合はSHA256ハッシュをフォールバック

2. ファイル処理

- ImporterSelectedFiles::import_photos() - メインのインポート処理
- 並列処理でファイルをコピー
- date/uuid/filename.jpg の構造で保存

3. データベース記録

- record_photos_meta_data() - SQLiteにメタデータを記録
- 星評価、コメント、撮影日時などを保存

4. 進捗管理

- ImportProgress - リアルタイムの進捗追跡
- Tauriイベントでフロントエンドに通知

主要な特徴

- UUID ベースの組織化: 同名ファイルの競合を防止
- 並列処理: 複数スレッドでの高速インポート
- メタデータ保持: ファイルの作成・変更日時を保持
- サムネイル生成: インポート後に自動生成
- レガシー対応: 既存のファイル構造との互換性維持

## スピード改善及びレジューム可能にする

1. 汎用的なjob queueをDB内に作る。以下のような構造を保存する
   - job_unit
     - schema:
       - id: string (UUIDv1)
       - jobs: json ([]string) ex: ["import", "thumbnail", "create_db"]
   - job_queue
     - schema:
       - job_unit_id
       - job
     - exapmle:
       - job_unit_id: uuid-version-1, job: `{"job_unit_id":"yyyy-mm-dd hh:mm:ss", "type":"import", target:["/path/to/import-target.jpg", "/phat/to/import-target2.jpg"]}`
       - job_unit_id: uuid-version-1, job: `{"job_unit_id":"yyyy-mm-dd hh:mm:ss", "type":"thumbnail", target:["/path/to/import-target.jpg", "/phat/to/import-target2.jpg"]}`
       - job_unit_id: uuid-version-1, job: `{"job_unit_id":"yyyy-mm-dd hh:mm:ss", "type":"create_db", target:["/path/to/import-target.jpg", "/phat/to/import-target2.jpg"]}`
2. インポート処理が実行された際、まず、job_unitを作成する。次に、job_queueにデータを入れる(import,thumbnail, create_dbの3種類)。
   job_unit_idには、UUIDv1で文字列を作成し、3つのjobに同じものを使う
3. background処理で、3つのjobをそれぞれ並列で動かす。job内のファイル処理自体も並列で行う(DBへのinsertは一括で良い)
   - アプリ起動時にもjob_unitをチェックし、残っている場合は、backgroundでjobを実行する
   - 並列度は、設定ファイルで管理する
4. jobが完了したら、job_queueからから削除を行う。すべてのjob_unit_idを処理し終えたら、job_unitからも削除する
5. jobが実行できない(例えば、import先のパスが存在しない、import元(target)のパスが存在しない)は、エラーモーダルを表示する
