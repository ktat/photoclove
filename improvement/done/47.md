# データベース検索パフォーマンスインデックス追加

## 概要

improvement #44で設計されたが未実装だった検索パフォーマンス最適化のためのデータベースインデックスを追加し、大量写真でのソート・検索処理を高速化する。

## ⚡ 緊急度：高（パフォーマンス問題）

### 現状の問題

**パフォーマンス問題**:
- 検索ソート機能は実装されたが、パフォーマンス最適化のインデックスが未追加
- 大量写真（1000件以上）でのソート処理が遅い（5-10秒）
- 複合フィルター検索で全表走査が発生（3-5秒）

**設計方針**:
検索・ソート頻度の高いカラムにインデックスを追加し、クエリパフォーマンスを大幅改善する。

## 実装対象ファイル

- `src-tauri/src/repository/meta_db/sqlite.rs:421-424` - init_db関数内のインデックス追加

## データベース分析

### 現在のテーブル構造
- **テーブル名**: `photo_metadata`（improvement #44 設計書の`photos`/`stars`ではなく単一テーブル）
- **重要カラム**: `exif_date_time_original`, `photo_date`, `star`, `path`

### 既存インデックス
- **`idx_photo_date`** on `photo_metadata(photo_date)` - 既存

### 必要なインデックス（improvement #44 設計書より）
1. **`idx_exif_date_time_original`** - EXIF撮影日時ソート最適化
2. **`idx_star`** - 星評価フィルター・ソート最適化  
3. **`idx_search_composite`** - 複合検索最適化

## 具体的実装変更

### A. `src-tauri/src/repository/meta_db/sqlite.rs` init_db関数内インデックス追加

```rust
// 行421-424周辺の既存 idx_photo_date インデックス作成の後に追加

// EXIF撮影日時インデックス（ソート最適化）
conn.execute(
    "CREATE INDEX IF NOT EXISTS idx_exif_date_time_original ON photo_metadata(exif_date_time_original)",
    [],
).map_err(|e| format!("Failed to create exif_date_time_original index: {}", e))?;

log::info!("Database index idx_exif_date_time_original created successfully");

// 星評価インデックス（フィルター・ソート最適化）
conn.execute(
    "CREATE INDEX IF NOT EXISTS idx_star ON photo_metadata(star)",
    [],
).map_err(|e| format!("Failed to create star index: {}", e))?;

log::info!("Database index idx_star created successfully");

// 複合インデックス（高速検索最適化）
// 検索頻度が高い組み合わせ: 撮影日時 + 星評価 + 追加日時
conn.execute(
    "CREATE INDEX IF NOT EXISTS idx_search_composite ON photo_metadata(exif_date_time_original, star, photo_date)",
    [],
).map_err(|e| format!("Failed to create search composite index: {}", e))?;

log::info!("Database index idx_search_composite created successfully");

log::info!("All database indexes for search optimization created successfully");
```

### B. インデックス作成順序の最適化

```rust
// インデックス作成は以下の順序で実行（既存 → 新規）
// 1. idx_photo_date (既存)
// 2. idx_exif_date_time_original (新規・単一カラム)
// 3. idx_star (新規・単一カラム)
// 4. idx_search_composite (新規・複合インデックス)
```

## パフォーマンス最適化戦略

### 1. 単一カラムインデックス
- **idx_exif_date_time_original**: ORDER BY exif_date_time_original の高速化
- **idx_star**: WHERE star = ? および ORDER BY star の高速化

### 2. 複合インデックス
- **idx_search_composite**: 複数条件での検索・ソートの最適化
- カラム順序: 選択性の高い順（exif_date_time_original → star → photo_date）

### 3. クエリ最適化効果
```sql
-- これらのクエリが高速化される:
SELECT * FROM photo_metadata ORDER BY exif_date_time_original DESC;
SELECT * FROM photo_metadata WHERE star >= 3 ORDER BY exif_date_time_original DESC;
SELECT * FROM photo_metadata WHERE star = 5 AND exif_date_time_original > '2024-01-01';
```

## パフォーマンス期待効果

### 1. ソート処理高速化
- **EXIF日時ソート**: 5-10秒 → 0.5-1秒
- **星評価ソート**: 3-5秒 → 0.3-0.5秒

### 2. 複合検索高速化  
- **星評価 + 日付フィルター**: 3-5秒 → 0.5秒未満
- **全表走査削除**: インデックススキャンに変更

### 3. メモリ使用量最適化
- ソート処理のメモリ使用量削減
- より効率的なクエリ実行プラン

## 注意事項

### 1. インデックスサイズ
- 各インデックスは追加ストレージを消費（数MB〜数十MB）
- 複合インデックスは単一インデックスより大きい

### 2. 書き込みパフォーマンス
- インデックス追加により写真追加時の処理が若干遅くなる可能性
- しかし検索頻度 >> 追加頻度のため、全体的にはパフォーマンス向上

### 3. 既存データベース対応
- 既存のphoto_metadataテーブルに自動的にインデックス追加
- データ移行やダウンタイムは不要

## 決定事項

- **インデックス追加**: 3つのインデックス（2単一 + 1複合）を追加
- **作成タイミング**: データベース初期化時（init_db関数内）
- **ログ出力**: 各インデックス作成成功時にログ出力
- **エラー処理**: インデックス作成失敗時は詳細エラーメッセージ
- **既存互換性**: 既存機能への影響なし
