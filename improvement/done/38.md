# Refactor PhotosList and PhotosListMini Components for Search Results Reuse

## Problem Analysis

The search functionality (improvement 37) has been implemented with dedicated components (`SearchPage.jsx` and `SearchResults.jsx`). However, analysis reveals significant code duplication with existing photo display components:

### Current Implementation Analysis

1. **PhotosList.jsx** (660 lines) - Main photo grid with date-based organization
2. **PhotosListMini.jsx** (640 lines) - Photo detail viewer with thumbnail strip
3. **SearchResults.jsx** (670 lines) - Search-specific photo display

### Code Duplication Issues

**Common Functionality Duplicated:**
- Thumbnail generation logic (getThumbnailSrc)
- Image caching mechanisms
- CSS style parsing (parseCssStyle)
- Photo navigation (prev/next)
- Star rating management
- Photo display layouts
- Video handling for mp4/webm files
- Error handling for missing images
- **Right panel tab management and animations**
- **Vertical tab button styling and behavior**
- **Panel open/close state management**

**Component-Specific Dependencies:**
- PhotosList: Heavily depends on date-based state management
- PhotosListMini: Tightly coupled with PhotosList's state
- SearchResults: Reimplements photo viewing from scratch

## Migration Strategy

### Right Column Tab Configuration
Different contexts will have different tab configurations:

**PhotosList Context (current behavior)**:
- Info tab: Photo metadata, EXIF data
- Editor tab: Photo editing tools

**Search Context (new requirement)**:
- Search tab: Search filters, saved searches, search history
- Info tab: Photo metadata, EXIF data  
- Editor tab: Photo editing tools

**BaseRightPanel Implementation**:
```jsx
// Example usage in PhotosListMini context
<BaseRightPanel
  context="photos"
  tabs={[
    { id: 'info', label: 'Info', component: PhotoInfo },
    { id: 'editor', label: 'Editor', component: PhotoEditor }
  ]}
  currentPhoto={currentPhoto}
  showSideMenu={showSideMenu}
  setShowSideMenu={setShowSideMenu}
  defaultActiveTab="info"
  {...otherProps}
/>

// Example usage in Search context  
<BaseRightPanel
  context="search"
  tabs={[
    { id: 'search', label: 'Search', component: SearchTools },
    { id: 'info', label: 'Info', component: PhotoInfo },
    { id: 'editor', label: 'Editor', component: PhotoEditor }
  ]}
  currentPhoto={currentPhoto}
  showSideMenu={showSideMenu}
  setShowSideMenu={setShowSideMenu}
  defaultActiveTab="search"
  {...otherProps}
/>
```

**Key Features to Preserve:**
- **Vertical tab buttons** with rotated text labels
- **Tab open/close animation** (menu-open/menu-closed classes)
- **Close button (×)** when panel is open
- **Focus management** (dummy-for-focus element)
- **Tab state persistence** during photo navigation
- **Responsive panel width** based on open/close state

### Backward Compatibility

4. Feature flags for new/old implementations
