# Implement Complete Save As Copy Feature for Editor

## Overview

The Editor's "Copy" button (should be labeled "Save As Copy") needs to be fully implemented to create new physical image files with CSS styles permanently applied, while integrating with the existing photo management system.

## Current State

The `saveAsCopy()` function currently shows "Save as copy functionality not yet implemented" message and does nothing.

## Complete Save As Copy Feature Requirements

When a user clicks the **"Copy"** button, the application should:

### 1. **Create New Physical Image File**
- Generate unique filename using pattern: `original-[sha256hash].jpg`
- Apply CSS styles permanently to image pixels (not just metadata)
- Save as new file in the same directory as original
  - To create styled image resembles Download file logic.
  - Consider creating image in frontend(React) and sent it to backend(Rust).
- CSS style normalization: SHA256 hash based on CSS with alphabetically sorted properties

### 2. **Store New Image in Database**
- Add to `photo_metadata` table with the new file path
- Copy relevant metadata from original photo (EXIF data, date, etc.)
- Set initial metadata: star rating, comments, etc.
- Link relationship: Possibly reference original photo as source

### 3. **Create Thumbnail**
- Generate thumbnail of the styled image using existing thumbnail generation system
- Store in thumbnail directory following UUID-based structure: `thumbnail_store/YYYY-MM-DD/[UUID]/filename.jpg`
- Update database to mark `has_thumbnail = true`

### 4. **Update UI/State**
- Refresh photo list to show the new image alongside original
- Update photo counts in date navigation
- Show success message with new filename
- Optionally navigate to the newly created image

### 5. **Integration with Existing Systems**
- Follow same directory structure as imports (date-based folders with UUIDs)
- Use existing thumbnail pipeline (same as import process)
- Respect existing photo filtering (appears in photo lists, search, etc.)
- Support all existing operations (star rating, comments, deletion, etc.)

## Technical Implementation Details

### Backend Requirements
- Create Tauri command `save_styled_copy` that:
  - Takes photo path and CSS style string
  - Generates SHA256 hash of normalized CSS
  - Creates new filename with hash
  - Applies styles to image and saves new file
  - Inserts new photo record in database
  - Triggers thumbnail generation job

### Frontend Requirements
- Update `saveAsCopy()` function in `PhotoInfo.jsx`
- Add proper error handling and user feedback
- Integrate with existing photo refresh mechanisms
- Show progress/loading state during processing

### File Organization
- Reuse import infrastructure for database insertion and thumbnail generation
- Use existing photo processing for style application and image writing
- Follow UUID pattern for file organization
- Trigger thumbnail job using existing job system
- Update photo lists using existing refresh mechanisms

## Benefits

This makes the "save as copy" feature create a **full first-class photo** in the system, not just an exported file, so users can:
- Manage styled copies just like original photos
- Apply further edits to styled copies
- Rate, comment, and organize styled versions
- Share styled images that work independently of the application
- Build collections of different styled versions of the same photo

## Use Cases
- Create styled versions without modifying originals
- Share styled images that look the same everywhere (no CSS dependency)
- Build a collection of different styled versions of the same photo
- Export final edited images while keeping them in the photo management system
