# PhotosList.jsx無限スクロール実装

## 目的
大量の写真を効率的に表示し、ユーザー体験を向上させる無限スクロール機能の実装

## 実装方法とソースコード変更箇所

### コードベース確認結果
- `src/App/PhotosList.jsx` (lines 1-1347) - メインコンポーネント。現在のページネーション機能を削除し、無限スクロールに置き換える
- `src/Scrollable.jsx` (lines 1-52) - スクロールコンポーネント。既存のイベントハンドラーを活用する
- 写真データは既にフロントエンド側で`allPhotosForCurrentFetch`→`filteredPhotos`のフローで完全に取得済み
- バックエンド実装は不要（データは既に存在）

### 問題点
- 大量の写真（数千〜数万枚）を一度に表示するとパフォーマンス問題
- 現在のページネーション（lines 1006-1009）は手動ページ切り替え
- スクロール体験が途切れる
- **機能重複**: 既存のスクロールベースページング(`photosScroll` line 913-939)と競合

### 既存のページネーション機能との関係
- **従来のページネーション削除**: datePage管理、has_next/has_prev等を削除
- **スクロールページング削除**: `photosScroll`関数、`nextPhotosList`関数を削除
- **簡素化**: 無限スクロールのみに集中、機能の重複を排除

### データフローの現状 (lines 326-367, 469-480)
```
allPhotosForCurrentFetch → filteredPhotos → photos.photos (ページ単位)
                                          → 画面表示
```

  const scrollContainer = e.target;
  const { scrollTop, scrollHeight, clientHeight } = scrollContainer;

const loadMorePhotos = useCallback(() => {
  if (isLoadingMore || displayedPhotoCount >= filteredPhotos.length) {
    return;
  }
  
  setIsLoadingMore(true);
  
  // 非同期で次のバッチを追加
  setTimeout(() => {
    setDisplayedPhotoCount(prev => 
      Math.min(prev + 50, filteredPhotos.length)
    );
    setIsLoadingMore(false);
  }, 100);
}, [isLoadingMore, displayedPhotoCount, filteredPhotos.length]);

function selectAllPhotoToSelection() {
    const selection = photoSelection.concat();
    const newSelectionDict = { ...photoSelectionDict };
    
    // 無限スクロール時の選択対象を明確化
    const targetPhotos = infiniteScrollEnabled 
        ? displayedPhotos  // 表示中の写真のみ
        : filteredPhotos;  // 全ての写真
    
    targetPhotos.forEach((photo) => {
        const path = photo.file.path;
        if (!newSelectionDict[path]) {
            selection.push(path);
            newSelectionDict[path] = true;
        }
    });
    
    setPhotoSelectionDict(newSelectionDict);
    setPhotoSelection(selection);
}

## 実装のメリット・デメリット

### メリット
- **コードの大幅簡素化**: 複雑なページネーション機能を削除
- **ユーザー体験向上**: 途切れないスムーズなスクロール
- **保守性向上**: 機能重複の排除、デバッグの容易さ
- **既存コンポーネント活用**: Scrollableコンポーネントをそのまま利用

### デメリット
- **大量データ時のメモリ**: 表示件数が増えるとメモリ使用量増加
- **初期読み込み変わらず**: 全データ取得時間は従来と同じ
- **後戻り困難**: 従来のページネーション機能完全削除
