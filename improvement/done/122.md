# 122: EXIF Thumbnail Support for Date/Album/Tag Views

## 概要

日付、アルバム、タグのview_modeで、サムネイルファイルが存在しない場合にEXIFサムネイルを自動取得する機能を実装する。

## 背景

### 現在の実装状況

**Import Mode**（参考実装）:
- `src/App/PhotosList/PhotoGrid.jsx` (line 158-228)
- サムネイルキャッシュがない場合、onErrorで `get_resized_image` を呼び出し
- バックエンドが自動的にEXIF thumbnailを抽出してキャッシュ
- 高速な画像表示を実現

**Library Mode (Date/Album/Tag Views)**（現在の問題）:
- `src/App/PhotosList/PhotoGrid.jsx` (line 109-118, 231-248)
- サムネイルがない場合、オリジナル画像を直接表示
- **`get_resized_image`を呼んでいないため、EXIF thumbnailは全く使用されない**
- `use_exif_thumbnail` configの影響も受けない（バックエンドコマンドを呼ばないため）
- 大きなファイルの読み込みでパフォーマンス低下の可能性

### バックエンドの実装

**`src-tauri/src/commands/image.rs::get_resized_image`** (line 154-261):
```rust
// Import Mode: 常にEXIF thumbnailを使用
// Library Mode: use_exif_thumbnail config がtrueの場合のみ使用
// ただし、現在のフロントエンド実装ではLibrary Modeでこのコマンドを呼んでいない
let should_use_exif = import_directory.is_some() || state.config.use_exif_thumbnail;

if should_use_exif {
    // EXIF thumbnail抽出ロジック (kexif crate使用)
    // 成功: キャッシュに保存して返す
    // 失敗: fallback（画像全体をリサイズ）
}
```

**重要**: 現在のフロントエンド実装では、Library Mode (Date/Album/Tag views) で `get_resized_image` を呼んでいないため、上記のEXIF thumbnail機能は実質的に Import Mode でのみ使用されています。

## 問題点

1. **パフォーマンス**: Library Modeでサムネイルがない場合、フルサイズ画像を読み込む
2. **一貫性の欠如**: Import Modeと Library Mode で動作が異なる
3. **EXIF活用不足**: ほとんどの写真にEXIF thumbnailが埋め込まれているのに活用されていない

## 提案実装

### アプローチ1: フロントエンド強化（推奨）

**ファイル**: `src/App/PhotosList/PhotoGrid.jsx`

**変更内容**:
Normal photos (line 231-248) のonErrorハンドラーを Import mode と同様のロジックに変更

```javascript
// 現在のコード (line 231-248)
if (photo.hasThumbnail && !e.currentTarget.dataset.triedOriginal) {
    e.currentTarget.dataset.triedOriginal = "true";
    // Try original image as fallback
    e.currentTarget.src = convertFileSrc(photo.displayPath());
} else {
    e.currentTarget.src = image_for_not_found;
}

// 提案コード
if (photo.hasThumbnail && !e.currentTarget.dataset.thumbnailGenerated) {
    // Step 1: Generate EXIF thumbnail on-demand (import modeと同様)
    e.currentTarget.dataset.thumbnailGenerated = 'true';
    invoke('get_resized_image', {
        pathStr: photo.originalPath,
        maxSize: 200,
        importDirectory: null  // Library mode
    })
    .then(() => {
        return invoke('get_thumbnail_path', {
            photoPath: photo.originalPath,
            importDirectory: null
        });
    })
    .then(cachePath => {
        const thumbnailUrl = convertFileSrc(cachePath) + '?t=' + Date.now();
        e.currentTarget.src = thumbnailUrl;
    })
    .catch(err => {
        // Fallback to original
        if (!e.currentTarget.dataset.triedOriginal) {
            e.currentTarget.dataset.triedOriginal = 'true';
            e.currentTarget.src = convertFileSrc(photo.displayPath());
        }
    });
    return;
}

// Step 2: Original fallback
if (!e.currentTarget.dataset.triedOriginal) {
    e.currentTarget.dataset.triedOriginal = 'true';
    e.currentTarget.src = convertFileSrc(photo.displayPath());
    return;
}

// Step 3: Final error image
e.currentTarget.src = image_for_not_found;
```

**メリット**:
- Import modeと同じロジックで一貫性がある
- バックエンド変更不要
- EXIF thumbnailが自動的にキャッシュされる

**デメリット**:
- 初回表示でonErrorトリガーが必要
- ネットワークリクエストが増える可能性

### アプローチ2: バックエンド強化

**ファイル**: `src-tauri/src/commands/image.rs`

**変更内容**:
Library Modeでも、キャッシュがない場合は常にEXIF thumbnailを試す

```rust
// Line 154-159 の変更
// 現在のコード
let should_use_exif = import_directory.is_some() || state.config.use_exif_thumbnail;

// 提案コード
// キャッシュがない場合は常にEXIF thumbnailを試す
let cache_exists = cache_path.exists();
let should_use_exif = import_directory.is_some()
    || state.config.use_exif_thumbnail
    || !cache_exists;  // キャッシュがない場合は必ずEXIF thumbnailを試す
```

**メリット**:
- 自動的にEXIF thumbnailを活用
- フロントエンド変更不要
- パフォーマンス向上（フルサイズ画像の読み込み回避）

**デメリット**:
- EXIF thumbnailがない場合、画像全体をリサイズする必要がある
- 初回リクエストが少し遅くなる可能性

### アプローチ3: Config変更（最もシンプル）

**ファイル**: `src-tauri/src/entity/config.rs`

**変更内容**:
`use_exif_thumbnail` のデフォルトを `true` に変更

```rust
// Line 36-38
fn default_use_exif_thumbnail() -> bool {
    true  // false から true に変更
}
```

**メリット**:
- 最小限の変更
- 既存のロジックをそのまま活用

**デメリット**:
- ユーザーが明示的にfalseに設定しない限り、常にEXIF thumbnailを試す
- 既存ユーザーの動作が変わる

## 推奨アプローチ

**アプローチ1 + アプローチ2 の組み合わせ**

1. **バックエンド**: アプローチ2を実装（キャッシュがない場合は常にEXIF thumbnail）
2. **フロントエンド**: Normal photosでもImport modeと同様のonError fallback chainを実装

これにより：
- 初回表示: EXIF thumbnailを自動取得
- キャッシュ命中: 高速表示
- EXIF thumbnailなし: 画像全体をリサイズしてキャッシュ
- 一貫性: Import modeと Library mode で同じ動作
