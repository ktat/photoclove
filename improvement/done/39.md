# Improvement 39: Fix Thumbnail Display Logic in PhotosListMini

## Problem

The thumbnail display logic in PhotosListMini.jsx shows inconsistent number of thumbnails and incorrect border positioning.

## Specification

### Photo Display Flow
1. User selects a date → Shows photo list (default: 20 photos)
2. User selects one photo → Photo displayed large with 9-thumbnail strip below
3. Thumbnail strip shows up to 9 thumbnails from ALL photos of that date

### Display Window Algorithm
```javascript
totalPhotos = total number of photos for the date
selectedIndex = index of currently selected photo (0-based)
maxDisplay = 9

if (totalPhotos <= maxDisplay) {
    startIndex = 0
    endIndex = totalPhotos - 1
} else {
    startIndex = Math.max(0, selectedIndex - Math.floor(maxDisplay/2))
    endIndex = Math.min(totalPhotos - 1, startIndex + maxDisplay - 1)
    
    // Adjust if near the end
    if (endIndex - startIndex + 1 < maxDisplay && endIndex === totalPhotos - 1) {
        startIndex = Math.max(0, endIndex - maxDisplay + 1)
    }
}

borderPosition = selectedIndex - startIndex
```

**Examples:**
- **6 photos**: Show all 6, no buttons
- **20 photos, photo 1**: Show 1-9, border position 1, ▷ visible
- **20 photos, photo 15**: Show 12-20, border position 4, ◁ visible
- **20 photos, photo 10**: Show 6-14, border position 5, both buttons visible

### Navigation Keys
- **Right/Left Arrow**: Move to next/previous photo
- **Up/Down Arrow**: Toggle thumbnail strip open/close

### Button Logic & Display Modes

#### Button Display
- **◁ visible**: When window can shift backward (photos before current window)
- **▷ visible**: When window can shift forward (photos after current window)

#### Display Modes

**Fixed Mode (no shifting possible)**
- Total photos ≤ 9, or at first/last window position
- Navigation only moves border within fixed window
- Examples: 6 photos total, photos 1-9 of 20, photos 12-20 of 20

**Dynamic Mode (shifting possible)**  
- Can shift in at least one direction
- Navigation recalculates window using Display Window Algorithm
- Example: photos 6-14 of 20, both directions available

### Navigation Behavior
- Keyboard navigation always works regardless of button visibility
- Fixed mode: only border moves within window
- Dynamic mode: window recalculates per algorithm
- Edge cases: First/last photo arrows do nothing, auto-load more photos if needed

## Implementation

1. Implement Display Window Algorithm
2. Add button visibility detection (shift possibility)
3. Apply Fixed/Dynamic mode logic in navigation functions
4. Update thumbnail rendering to follow algorithm

## Test Cases

1. **≤9 photos**: All shown, fixed mode
2. **>9 photos**: Algorithm positioning, mode switching  
3. **Navigation**: Both modes, edge cases
